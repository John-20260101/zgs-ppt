## 0 结论摘要

链路是通的：官方示例 `--audit-only`、`build`、`check_deck`、`verify_pptx` 全绿，13 页成稿渲染后无越界、无压字。**问题集中在三类**：

1. **一个 P0 缺陷会让「套学校模板」这条主推路径直接产出坏文件**（zip 内 part 重名，LibreOffice 打不开，PowerPoint 大概率弹「修复」）。而 CI 恰好没有覆盖 `--template`，所以它活到了 v0.4.3。
2. **文档承诺的检查有相当一部分没有实现**：单页字数上限、备注上限、`紧度>100%` 门禁、非法输入校验，全靠模型自觉；脚本侧只在「>26 字标题」和「备注偏短」两处真正拦过。
3. **两处静默丢字段/静默兜底**：`compare` 的来源行不上版面，未知 `theme`/`group` 被悄悄替换。这类「看起来成功」的失败，正是这个技能自称要防的东西。

优先级建议：F1–F4 立即修（产不出正确成品 / 违背自家红线），F5–F10 本轮修（承诺未兑现 + 版面质量），F11–F16 随文档与 CI 一起清（一致性）。

## 1 复现环境与方法

```bash
# 全链路在副本里跑，不动仓库
T=/tmp/zgs-test-$$
rsync -a --exclude .git ~/Desktop/Program/deepseek/zgs-ppt/ "$T/skill/"
cd "$T/skill"

python3 scripts/build_pptx.py examples/case-wang/王某某-outline.json -o "$T/base.pptx" --report "$T/base-audit.md"
python3 scripts/check_deck.py "$T/base.pptx" --expect 13   # v0.4.3 的示例当时是 13 页
python3 scripts/verify_pptx.py "$T/base.pptx" --expect-pages 13 --json "$T/verify.json"
```

三层手法：

1. **sentinel 大底**：构造一份 17 页的 outline，每页的每个字段埋唯一串（`S7-v1`、`S10-note`…），再逐页把 pptx 文本与期望串对齐 → 找出「文档声明上版面、实际没上」的字段。
2. **边界用例**：未知 theme/group、字段类型错（`bullets: "不是数组"`）、超长备注、超限字数、4:3 模板、竖/横图、人为溢出。
3. **渲染复核**：`soffice → pdf → pdftoppm → png`，再用 `pdftotext -bbox` 量每页正文最低点，人眼看图。

## 2 P0：产不出正确/可打开的成品

### F1 `--template` 产出损坏包（模板原页残留 + zip part 重名）

**位置** `scripts/build_pptx.py:970-978`

```python
stale = len(prs.slides)
if stale:
    sld_ids = prs.slides._sldIdLst
    for sid in list(sld_ids):
        sld_ids.remove(sid)          # 只从 sldIdLst 摘掉，slide part 与 rel 仍在包里
    print(f"! 模板含 {stale} 页示例内容，已清空（母版与版式保留）", file=sys.stderr)
```

python-pptx 新增幻灯片时按 `slide{n}.xml` 取「当前未被占用」的名字；旧 slide part 没被释放，仍占着 `slide1.xml`，于是新封面被写进同名 part。

**证据**

```bash
# 1) 包内重名
python3 -c "import zipfile,collections;z=zipfile.ZipFile('t43b.pptx');\
print([k for k,v in collections.Counter(i.filename for i in z.infolist()).items() if v>1])"
# ['ppt/slides/slide1.xml', 'ppt/slides/_rels/slide1.xml.rels']

# 2) 同名 part 里还是模板的旧文字
# occurrences: 2
#   text: b'模板示例标题 | 示例正文'      ← 模板原页
#   text: b'c | s | a　·　b　·　c　·　d'  ← 新封面写进了同名条目

# 3) 打不开
soffice --headless --convert-to pdf --outdir conv t43b.pptx
# Error: source file could not be loaded

# 4) 不带 --template 的同内容 deck 正常转换
soffice --headless --convert-to pdf --outdir conv nontmpl.pptx
# convert ... -> conv/nontmpl.pdf
```

**影响** 手机/评委机 PowerPoint 打开会走「修复」，修复结果**丢哪一页不确定**；`--pdf` 静默失败（见 F8）；4:3 模板支持（代码第 5 行自述的设计点）等于不可用。

**修法（已验证）**

```python
for sid in list(sld_ids):
    rId = sid.get(qn("r:id"))
    if rId:
        prs.part.drop_rel(rId)   # 释放 slide part + rel，再摘 sldId
    sld_ids.remove(sid)
```

修后 `dup entries: []`，`soffice` 转换成功，4:3 版面正常（见 `evidence/06-template-4x3-after-fix.png`）。

### F2 `compare.note` / `compare.source` 静默丢弃

**位置** `scripts/build_pptx.py:454-489`（`s_compare` 全函数没有读 `note`/`source`）

**证据** sentinel 测试 17 页型，只有 compare 丢内容：

```
P01 cover    丢失=无     P10 compare  丢失=['S10-note', 'S10-source']
P02 agenda   丢失=无     P11 matrix   丢失=无
...                       P17 closing  丢失=无
```

现成示例 P4 就命中（`examples/case-wang/王某某-outline.json` 的 compare 页写了 `"note": "来源：某医养结合养老机构 2025 年照护主管招聘公告（节选，原文待补）"`），渲染出来整页没有来源行：

```
--- P4
差距 / 公告 4 条硬要求，我够 2 条 / 招聘公告硬要求 / 我的现状（2026.11）/ VS / 就业赛道·职教组 / 04 / 13
```

**影响** 直接违背 SKILL.md §3.2「数字要有口径」与 §10 红线「口径不写旧版」；更糟的是 `spec_chars()` 把这 30 字算进页字数，让 `page-thin` 判断偏乐观。

**修法** 加一行 `数据来源：{source or note}` 于 `FOOT_Y-0.42`（与 bullets 同款）；`spec_chars` 改用白名单 `VISIBLE_KEYS`，只计真正上版面的键。

### F3 `theme` / `group` 静默兜底

**位置** `build_pptx.py:966-968`、`982-984`、`1021`

```python
theme = Theme({"name": outline["theme"], **DEFAULT_THEMES.get(outline["theme"], {})})   # 未命中 → 只剩 name
label = outline.get("group_label") or GROUPS.get(grp, GROUPS["Z1"])[0]                 # Z9 → 按 Z1 兜
label, dims, (lo, hi) = GROUPS.get(group, GROUPS["Z1"])                                # 页数/维度也按 Z1
```

**证据** 把示例改成 `"theme":"spark"`、`"group":"Z9"`：

```
✓ 生成 bad-theme-group.pptx（13 页）
- [W] page-count：成长赛道·高教组 建议 15–20 页，当前 13 页
- [W] dim-missing：未标注以下评分维度：学习实践行动、优化改进
```

输出 exit 0。in-deck 页脚写着「成长赛道·高教组」，而这份 deck 实际是 Z5 就业赛道；配色被换成 academic，`name` 字段却是 `spark`。**选手交上去页脚赛道写错，是评委第一眼能看见的错。**

**修法** `validate()` 加 `group-invalid` / `theme-invalid`（E 级、退出 2）；`group_label` 与 `GROUPS[group][0]` 不一致时报 `label-mismatch`（W）。

### F4 字段类型不校验，字符串被按字符迭代

**位置** `build_pptx.py:285-301`（`items = spec.get("bullets") or []` 后直接 for）

**证据** `{"type":"bullets","bullets":"不是数组"}` →

```
✓ 生成 bullets-str.pptx（3 页）        # exit 0，无 E 告警
| 2 | bullets | t | 45% | 12 | — | — |   # 4 条要点其实是 4 个汉字
```

`validate()` 只查 `type` 存在与否（918-929），不查任何字段形状。所以 `bullets`/`cards`/`items`/`quadrants`/`headers` 写错类型时，产出的都是「能打开但内容错位」的文件。

**修法** 加 `SPEC_RULES` 表（见 §4.1-3），不满足 → E `field-type` / `field-missing`。

## 3 P1：承诺的检查没实现 / 版面缺陷 / 安装路径坏

### F5 文档化上限与门禁全线未实现

`references/slide-types.md:26-42` 给了每种页型的字数上限，`SKILL.md:245-247` 给了备注区间与「紧度 >100% 不许进 Step 6」的硬门禁。实测：

| 声明 | 用例 | 实际 |
| :--- | :--- | :--- |
| cover `title ≤ 20 字` | 25 字封面标题 | 无告警（只有全局 `title-long` 管 >26） |
| bullets 单条 ≤ 48 字 | 56 字单条 | 无告警 |
| compare 单条 ≤ 28 字 | 30 字单条 | 无告警 |
| timeline `what ≤ 36 字` | 40 字节点 | 无告警 |
| 紧度 >100% 不许渲染 | 372% 紧度、3074 字页 | `exit 0`，只是 W |
| 备注 1750–1900 / 1500–1650 | 3000 字 ≈ 11′09″ | 无告警（只查「偏短」，`notes-short`） |

```
| 2 | bullets | 六条四百字要点 | 372% | 3074 | — | [W] 文字缩到下限仍溢出（372%）…
overall exit=0
备注口播：合计 3000 字 ≈ 11′09″（269 字/分；…）      ← 超上限 76%，无任何 W
```

**影响** 「审计」在真实使用中只防了「标题太长」和「字数太少」，而这两条恰好不是最常犯的错。选手最常犯的是「一页塞六条长句」「备注写成逐字稿几千字」。

### F6 版面空白无信号，且 5 个页型故意留白

**位置** `s_cards`(695-698)、`s_detail`(662-674)、`s_process`(742-763)、`s_matrix`(782-796)、`s_kpi`(376-382)

- `cards` n=3：`ch = BODY_H - 0.42 = 4.13in`，卡片正文只占约 30%（SKILL.md:318 自己承认了「三卡会被撑到全高、文字只占三成」），但**脚本只给建议、不改版面**；
- `detail` 4 块：块高 4.43in，正文 1 段 40 字只填 0.3in；
- `process` 5 步：`h = BODY_H-0.4 = 4.15in`，detail 只占 1in；
- `matrix`：`ch = (gh-0.22)/2 ≈ 2.2in`，每格正文 30 字；
- `kpi`：4 卡 `card_h` clamp 到 2.05–2.95in，卡内容实际约 1.6in（`evidence/02-kpi-cards-half-page.png`），卡下方空一屏。

用 `pdftotext -bbox` 量正文最低点（版心下沿按 466pt 估）：

| 页 | 类型 | 正文最低点 | 下方空白 |
| --: | :--- | --: | --: |
| 2 | agenda | 323.8pt | **142pt** |
| 4 | compare | 321.0pt | **145pt** |
| 9 | cards(3) | 300.8pt | **165pt** |
| 12 | twocol | 310.0pt | **156pt** |

审计对这四页一条告警都没有。`build_pptx.py` 其实已经把每个文本框记在 `ctx.boxes`（第 138 行），**有数据却没用**。

**修法** ① 面板内正文改 `MSO_ANCHOR.MIDDLE`，让留白变成对称呼吸而不是「文字贴顶」；② 新增 `page-empty-bottom` 信号（正文框最低点 < 4.7in 即 W）；③ `kpi` 卡高按实测内容 clamp 上限抬到 3.40in。

### F7 `section` 页码大数字对比度 ~1.05:1

**位置** `build_pptx.py:270-271`

```python
add_text(..., num, size=78, bold=True,
         color=t.band if t.band != RGBColor(255, 255, 255) else hexc("#EDEFF4"))
```

academic 主题 `band = #F1F4F9` 画在 `bg = #FFFFFF` 上：相对亮度 0.89 vs 1.00 → 对比度 **1.05:1**（WCAG AA 正文门槛 4.5:1）。渲染出来几乎是一个白块（`evidence/01-section-number-contrast.png`）。

**修法** 用 `t.muted`（academic `#6C7A8C` → 4.6:1）；band 留给色带与卡片底。

### F8 `--pdf` 成功提示不可信

**位置** `build_pptx.py:1206-1207`

```python
convert_pdf(out)                            # 返回值被丢掉
print(f"✓ 导出 PDF：{os.path.splitext(out)[0]}.pdf")
```

F1 的模板坏包正是走这条路：`soffice` 报 `source file could not be loaded`，脚本仍打印 `✓ 导出 PDF`。走 preview 分支时同理（1199-1202 只在成功时打印，但无 else 提示）。

**修法** 检查返回值，失败打印 `✗ 未生成 PDF（soffice 无法加载该文件）` 并在 `--pdf` 下计入 hard。

### F10 §3.1 一致性检查脚本对格式不符的 md 报「全部对齐」

**位置** `SKILL.md:112-136`

在示例目录跑文档给的 snippet：

```
JSON 13 页 ｜ 大纲：封面封底主标题 0、内容页 0
全部对齐
```

该示例 md 是 0.2.0 遗留格式（`## P1 封面 · cover`、`- 文案：…`），两个正则 0 匹配，脚本却输出「全部对齐」——**这是最坏的一种检查**：它会在真正该拦的时候发绿灯。另外 md 内容页多于 JSON 时 `sl[i-1]` 会 IndexError。

**修法** 抽出 `scripts/check_outline.py`，把「0 匹配」当硬失败（附示例格式），并校验页数一致。
